## 0. 使用说明

| 标记 | 含义 |
|---|---|
| **P0** | 阻塞项，必须通过才能进下一阶段 |
| **P1** | 重要项，可在当前阶段记录后延期，但交付前必须清零 |
| **自动** | 由 Vitest / 脚本断言，纳入 `pnpm test` |
| **人工** | 需在浏览器中人工核对，附截图或录屏 |
| **GWT** | Given（前置局面）→ When（操作）→ Then（期望） |

**完成定义（DoD）**：某阶段所有 P0 项通过 + `pnpm test` 全绿 + `pnpm build` 无报错 + 打包体积不超预算，方可标记该阶段完成。

**测试数据约定**：规则用例一律写成"局面构造 + 起止点 + 期望结果"，不放图片、不依赖手点。目前局面用测试文件内的构造器内联（`makeBoard` / `makeState`），**没有**独立的 `tests/fixtures/` 目录。

### 3.2 将军与终局（P0，自动）

| 编号 | 前置 | 操作 | 期望 |

| R-CK-01 | 红车正对黑将一线，中间无子 | 查询黑方 | `isInCheck(black) = true`，且 HUD 应给出提示（人工复核） |
| R-CK-02 | 黑将被将军，存在唯一应将 | 调用 `legalMoves` | 只返回能解除将军的招法（含垫子、吃子、移将） |
| R-CK-03 | 黑将被将军且无任何合法招 | 查询状态 | `status = over`，`winner = red`，`reason = 'checkmate'` |
| R-CK-04 | 黑方无合法招且未被将军（困毙 fixture） | 查询状态 | `winner = red`，`reason = 'stalemate'` |
| R-RP-01 | 同一方连续将军使局面三次重复 | 落子后 | 判该方负，`reason = 'perpetual-check'` |
| R-RP-02 | 同一局面三次重复但非长将 | 落子后 | 判和，`reason = 'draw-repetition'` |
| R-RP-03 | 60 回合内无吃子 | 落子后 | 判和，`reason = 'draw-60'` |
