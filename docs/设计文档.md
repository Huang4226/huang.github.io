## 1. 产品概述

一个可在浏览器离线运行的象棋小游戏，首页提供两个模式入口：

1. **经典双人**：标准 9×10 中国象棋，双人同屏轮流，规则与民间通行规则一致，含简单 AI。
2. **三人逐鹿**：三家（红 / 黑 / 白）同屏轮流，规则**完整套用经典象棋**，棋盘改为"三翼 + 逐鹿台"三向棋盘；新增独有机制"**杀将收编**"。

视觉素材直接取自现有 `picture/` 目录（21 枚棋子贴图、木纹底图）。

### 1.1 设计目标

| 目标 | 说明 |
|---|---|
| G1 规则可信 | 走法、将军、将死、困毙、长将全部经自动化测试覆盖；棋子行为与民间象棋一致，不允许"差不多" |
| G2 三人模式有辨识度 | 棋盘拓扑、收编机制、渡口/三岔口三个机制共同形成独特体验，而不是"双人棋盘塞进去三个人" |
| G3 小体积、零后端 | 发布包 < 1.5 MB，纯静态，双击/静态服务器即可玩，无需网络与账号 |
| G4 可维护 | 引擎与渲染解耦；两套棋盘共用同一套引擎，新增"四人"或换棋盘只改数据文件 |

### 1.2 非目标（本期不做）

联机对战、账号系统、排行榜、残局编辑器、移动端手势与打包、皮肤系统、真人语音。除双人 AI 外的 AI 后置（见 11 章）。

## 2. 术语表

| 术语 | 含义 |
|---|---|
| 一翼 / 方阵 | 三名玩家各自的 9×5 本方半场，含九宫、炮兵位 |
| 逐鹿台 | 三条河道围出的中央三角形空档，三家共用的公共战场；**不设棋盘格**，只作为过河桥的汇聚区 |
| 渡口 | 每翼 rank 4 的 9 个交点，过河桥的起点 |
| 三岔口 | 三个渡口顶点（各翼 (4,4)），同时属于相邻两个方阵；三处两两相连成小倒三角 |
| 架 | 一套方向体系。方阵用 4 向（正交）；渡口顶点连着两条桥，可在此换架 |
| 换架 | 一手棋只沿一条射线行进，因此"转向"只能发生在渡口/三岔口这类双属点上 |
| 收编 | 杀将后，败方剩余的 车/马/炮 **与未过河的兵/卒** 变色归胜方指挥；已过河的兵/卒与防御子直接移出棋盘 |
| 格点图 | 用"节点 + 射线 + 跳跃"表达棋盘拓扑的数据结构，引擎不感知几何 |

## 3. 技术选型

### 3.1 选型结论

**Vite + TypeScript + Canvas 2D + Vitest**（方案 B）。

| 维度 | 结论 | 理由 |
|---|---|---|
| 构建 | Vite | 产物极小、`pnpm dev` 热更新、`pnpm build` 直接出静态站 |
| 语言 | TypeScript（strict） | 规则引擎全是坐标与状态变换，类型能挡住一大类低级错误 |
| 渲染 | Canvas 2D（逻辑坐标 + DPR 缩放） | 棋盘线 100+ 条、动态高亮、不涉及 DOM 布局，Canvas 最直接 |
| 测试 | Vitest | 走法用例是纯函数级测试，不需要浏览器环境 |
| AI | 手写 negamax + alpha-beta（Web Worker 预留） | 第三方象棋库均不支持三向棋盘 |

### 3.2 体积与内存预算（对应"50MB 以内"要求）

| 口径 | 预算 | 说明 |
|---|---|---|
| 发布产物 JS | ≤ 150 KB（minify 后） | Vite 不回填框架，产物≈自有代码 |
| 发布产物 CSS | ≤ 20 KB | |
| 素材 | 724.5 KB（现有 `picture/`，不重复打包） | JPEG 底图可再压 30% |
| **发布包合计** | **≤ 1.2 MB** | 远低于 50 MB 上限 |
| 开发期 `node_modules` | 60–120 MB | 仅本机，不随游戏分发 |
| 浏览器运行内存 | ≤ 150 MB / 标签页 | 主要来自 Canvas 位图，与框架无关 |
| 首屏可交互 | ≤ 1 s（本地） | 素材总量 < 1 MB，无需懒加载 |

> 结论：没有任何一项会把发布包推到 50 MB。若后续要"双击 index.html 即玩"，可在 M6 追加一个 `build:single` 脚本把产物内联为单文件（不改架构）。

## 5. 核心数据模型

```ts
/** 世界坐标系：像素，原点在棋盘外接框左上角，y 向下 */
interface BoardNode {
  id: number;
  x: number; y: number;
  /** 三人局该点所属方阵（0/1/2）；经典棋盘为 undefined */
  wing?: number;
  /** 方阵内坐标（经典棋盘全盘通用；三人局为该点所属方阵的局部坐标） */
  file?: number;
  rank?: number;
  /** 所属架：三人局每个节点只挂本方阵（`['s0']`…）；渡口顶点的"双属"靠 bridges 表达 */
  frames: Frame[];
  tags: string[];           // 'ferry' | 'palace:s0' | 'base:s0' | 'junction' …
}

/** 棋子。注意"过河"是棋子的状态，不是格点属性 */
interface Piece {
  team: Team;                 // 'red' | 'black' | 'white'
  kind: PieceKind;            // general/advisor/elephant/horse/chariot/cannon/pawn
  /** 仅兵/卒使用：是否已过河。一经获得不可逆；收编时据此决定"归降"还是"移出" */
  crossed?: boolean;
}

interface Ray {            // 从某节点出发的一整条直线，nodes 不含起点，按距离升序
  dir: number;             // 方向 ID（翼内 1/2/4；上向为 3，顶点处分叉成两条）
  nodes: NodeId[];
}

interface JumpMove {       // 马/相/象：一次跳跃
  target: NodeId;
  leg?: NodeId;            // 蹩腿点（马）
  eye?: NodeId;            // 塞象眼点（相/象）
}

interface Topology {
  name: 'classic' | 'three';
  nodes: BoardNode[];               // 按 NodeId 索引
  rays: Map<NodeId, Ray[]>;
  jumps: Map<NodeId, JumpMove[]>;
  palaces: Map<Frame, NodeId[]>;    // 架 → 九宫 9 点
  startLayout: PieceInit[];
  boardBox: { w: number; h: number };
  segments: Array<[NodeId, NodeId]>; // 渲染线段（经典中路竖线在河界断开）
  gap: number;                      // 默认格距，用于棋子尺寸与吸附半径
  palace(team: Team): ReadonlySet<NodeId>;
  ownHalf(n: NodeId, team: Team): boolean;      // 相/象不可过河的依据
  pawnForward(n: NodeId, team: Team): NodeId[]; // 兵/卒前进（渡口处为过桥落点）
  pawnSide(n: NodeId, team: Team): NodeId[];    // 兵/卒横向落点
}
```

### 5.1 节点 ID 约定

- 双人：`id = rank * 9 + file`（0..89），file 0..8，rank 0..9，rank 0 为红方底线。
- 三人：`id = s * 45 + rank * 9 + file`（0..134）；每个节点只挂一个 `frame`（本方阵），渡口顶点靠 `bridges` 表达与相邻翼的连通。

### 5.2 引擎的走法契约（关键不变式）

> **一手棋只能沿一条射线滑行，或完成一次跳跃；列线在渡口接上对岸列线（T-12），横线不跨河。**

由此自动得到三个机制，不需要额外代码：

1. 车/炮在方阵内只能走方阵的行列；**列线走到渡口就接上对岸那条列线**（T-12），所以能一着沿中线过河；
2. 横线（rank 方向）不过河，只在本翼内；
3. 渡口顶点连着两条桥，从顶点出发的射线会**分叉成两条**，车/炮各走一条——这是"顶点能落脚、却只能顺着两座桥出去"的原因。

标准 9 列（file 0–8）× 10 行（rank 0–9）交点阵，共 90 交点。

绘制线段数 = 横 10×8 = 80 段 + 竖 9×9 − 7（中路 7 条竖线在河界断开）= 154 段。

| 项目 | 定义 |

## 7. 三人棋盘拓扑（三翼 + 渡口互连）

### 7.1 结构（现行实现）

> 本节是**实际落地**的拓扑。7.1.1 保留 v1.1 纸面方案仅供回溯，不可与本节混用。

- **三翼**：每翼 = 9×5 交点（file 0–8 × rank 0–4）的方阵，含九宫（file 3–5 × rank 0–2）、16 枚棋子；三翼合计 **135 个交点**，中央**没有**独立棋盘区。
- **渡口**：每翼 rank 4 的 9 个点（`tags: ['ferry']`），是过河桥的起点。
- **过河桥**：三个渡口顶点（各翼 (4,4)）**两两相连**，在盘心围成边长约 58 px 的小倒三角；其余 24 个河沿点各自连到**最近的对岸河沿点**（阈值 260 px）。
- **三岔口**：即三个渡口顶点，各同时属于相邻两个方阵，是"换架"点。

```
                    ▲ s2（白）
                   ╱ ╲
                  ╱   ╲
       s0（红）  ◀── 渡口互连 ──▶  s1（黑）
                  ╲   ╱
                   ╲ ╱
                    ▼
```

### 7.1.1 旧方案：三翼 + 逐鹿台（v1.1 纸面设计，已废弃）

- **逐鹿台**：边长 9 交点的正三角形区（三角晶格），用重心坐标 `a+b+c=8, a,b,c≥0` 表示，共 45 个交点。
- **渡口**：s 翼的 rank 4 那 9 个点 = 逐鹿台第 s 条边（`坐标 s = 0` 的边），点对点重合。
- **三岔口**：逐鹿台 3 个顶点，各由两个方阵共用。

### 7.2 坐标与映射（旧方案，已废弃；现行实现见 7.2.1）

三翼局部坐标 `(file, rank)`；逐鹿台重心坐标 `(a, b, c)`。

翼 s 贴逐鹿台第 s 条边，渡口映射：

| 翼 s | 所在边 | file 0 ↔ | file 8 ↔ | 与谁共用角 |
|---|---|---|---|---|
| s0 红 | a = 0 | (0,8,0) | (0,0,8) | file0→s2 角；file8→s1 角 |
| s1 黑 | b = 0 | (0,0,8) | (8,0,0) | file0→s0 角；file8→s2 角 |
| s2 白 | c = 0 | (8,0,0) | (0,8,0) | file0→s1 角；file8→s0 角 |

渡口点 `(s, file f) ↔ (a,b,c)` 满足 `边坐标 = 0`、`中间坐标 = f`、`末坐标 = 8−f`（按上表顺序展开）。

> **手性闭环**：每翼的 `file 0` 角恰为前一翼的 `file 8` 角（s0→s2→s1→s0），因此三翼的 file 递增方向绕盘一圈一致，不会出现某一翼左右镜像的合法性陷阱。M4 的旋转自同构检查（T-03）就是用来钉死这一点的；该检查目前只有标定残差记录，尚未写成直接断言。

**世界坐标**：翼 s 的局部坐标经旋转 `θ_s = 120°·s + θ0` 与平移得到：

```
world(s, f, r) = R(θ_s) · ( (f - 4)·G , (4 - r)·G ) + C_s
```

- `G` = 设计基准格距：**三人局 48 px**、双人局 50.1 px。渲染时整体按 `min(视口宽/盘宽, 视口高/盘高)` 等比缩放，棋子贴图随 `G` 同步缩放；
- `C_s` = 该翼原点，由三翼互成 120°、中心对称反推（保证三翼九宫到底盘中心距离相等）；
- 逐鹿台节点 `(a,b,c)` → 由三个顶点世界坐标做重心插值：`P = (a·V_a + b·V_b + c·V_c) / 8`。

> **v1.2 实测修正**：上面这套"格距 `G` + 旋转"的公式只适用于纸面设计的正三角棋盘。
> 实际采用的底图 `picture/三人地图.png` 是手绘风格的扇形网格——格距从底线到渡口越来越大
> （38–116 px），尺规画出来的仿射矩阵最多只能把 96 个格子中心拟合到 ±20 px，
> 棋子会明显偏离交点。因此三人局**放弃公式生成坐标**，改为逐点标定，见 7.2.1。

### 7.2.1 三人地图的交点标定（v1.2）

坐标不再是公式产出的，而是**从底图的墨线里量出来的 135 个点**，存在
`src/topology/three-coords.ts`（`id = s*45 + r*9 + f`）。标定三步全部可复现：

| 步骤 | 命令 | 做什么 | 产物 |
|---|---|---|---|
| ① 找格子 | `python scripts/calib-three.py` | 底图背景浅色，泛洪得到 96 个格子内部的中心；再按"方向分类的 BFS"把每翼 32 个格子排成 8 列 × 4 行 | `debug/cells.json`、`debug/cellmap.json` |
| ② 定交点 | `python scripts/refine-three.py` | 每个交点取相邻 4 个格子各退半格的平均作初值；再把交点吸附到它几条**出边**的墨线交点：每方向在 ±8°、±12 px 内搜最贴墨的直线，多线做最小二乘求交 | `debug/three-nodes.json` → **`src/topology/three-coords.ts`** |
| ③ 核对 | `python scripts/overlay-three.py debug/three-nodes.json` | 把交点（红点）与连线（蓝线）叠回底图，肉眼验 | `debug/overlay-snapped.png` |

结果：135 个交点与底图十字线偏差 **≈ 1 px**；最短交点间距 38 px（跨河两翼的角点），
棋子直径 42 px（`gap = 57` × 0.74）。三翼的 120° 自同构残差 < 1.5 px，
三个渡口顶点构成边长 58 px 的正三角、中心恰好落在盘心 (511, 511)。

> **为什么歪线不影响规则**：坐标只服务于"画在哪、点到哪"。
> 走法、将军、飞将、吃子判定全部走拓扑结构（`rays` / `jumps` / `bridges`），
> 一条线是不是画直了、转角多少度，规则引擎根本不看。
> 三条"河"只是把三翼隔开：车/炮的列线在渡口接上对岸（T-12）；兵/卒过河必须走 `bridges`（渡口点对点相连），
> 这也是三人局比双人局**多出来的那一条路**。
>
> 马不套理想方格，而是在这张图上**逐格数路线**（直行两格 + 拐一格，第一格是蹩腿点），
> 所以"日"字在这张被拉歪的图上依然站得住，倒三角处也不会算出奇怪的角度。
>
> 折角处怎么处理：**不处理，因为线本来就该接上**。
> 拓扑构造射线时，列线走到渡口就把对岸那条列线接在后面（T-12），
> 于是车炮在这张歪图上能一着过河；帅的射线也顺着这条线延伸到对岸，照面（T-7）是自然结果。
> 只有兵/卒仍按"到渡口再跨一步过桥"的规则（T-8）——它们本来就不是射线兵种。

> 生成器 `scripts/refine-three.py` 负责产出整张坐标表，**允许**在 `three-coords.ts` 里看到具体数字——
> 它是标定结果而不是手填配置，重新跑一遍脚本会得到同一张表。

### 7.4 邻接与射线（现行）

| 区域 | 方向数 / 射线数 | 车/炮 | 马（T-13） | 兵/卒（T-8） |
|---|---|---|---|---|
| 翼内（rank 0–3） | 4 向 / 4 条 | 沿行、列；列线走到渡口就接上对岸列线 | 逐格"直行两格 + 拐一格"，腿=第一格 | 未过河：rank+1 |
| 渡口（rank 4，非顶点） | 4 向 / 4 条（上向接唯一一座桥） | 上行经桥进入对岸列线 | 同上，可"斜日"过河 | 过桥；已过河还可横走/深入 |
| 渡口顶点（三岔口） | 4 向 / 5 条（上向分叉成 2 条） | 两座桥分叉成两条射线，各走一条 | 5 条腿、12 落点、覆盖三翼 | 两座桥任选；已过河同上 |
| 他翼（兵已过河） | 4 向 / 4 条（上向接桥） | 沿该翼列双向滑行 | 同上 | 深入 rank−1 或横走；**不能回河道边** |
| 他翼·将死后 | 同上 | 同上 | 同上 | 可 rank+1 **掉头**回渡口，再转战第三翼 |

> 马没有固定的"落点表"：它在这张被拉歪的图上逐格数路线（直行 ≤60°、拐弯 66–132°），
> 同一落点有多条路线时只留一条腿（先比少过河，再比拐角接近 90°，最后比总弯度），
> 因此"腿被堵就跳不过去"；跳法保证对称（能跳过去就能跳回来）。

> **实现注记（M4 实测）**：三岔口是三角形的顶点，从顶点出发的直线只有两条——它们**恰好沿着三角形的两条边走**。
> 因此三岔口上的车/炮可以沿两条边推进、也可以转入任一相邻翼的行列，但**一条直线进不到对岸翼的腹地**；
> 想深入，必须先过桥再转向。这是拓扑本身的性质，不是实现取舍。

## 8. 规则规格

### 8.1 通用走法（双人、三人翼内完全一致）

| 兵种 | 走法 | 限制与判定 |
|---|---|---|
| 帅/将 | 九宫内横竖 1 步 | 不出九宫；**双人局**：两帅不得同列无子相隔（照面）；**三人局**：隔河照面同样算将军（T-7，只改攻击判定、不产生走法） |
| 仕/士 | 九宫内斜 1 步 | 只能落在九宫 9 点中沿对角线的 5 点之间 |
| 相/象 | 田字斜 2 步 | 塞象眼（田心点有子则不可走）；不得过河；三人局**只在方阵内**行走，不进逐鹿台 |
| 马 | 日字 | 蹩马腿（第一直行邻点有子则不可走） |
| 车 | 直线任意格 | 不可越子；三人局受"架"限制（见 5.2） |
| 炮 | 直线任意格 | 移动不吃子；吃子时起点与目标之间**恰有 1 子** |
| 兵/卒 | 前进 1 步；过河后可横走 1 步 | 不可后退 |

### 8.2 双人胜负

| 情形 | 判定 |
|---|---|
| 帅/将被吃 | 负（实战中不会发生，引擎以"将死"终止） |
| 被将军且无合法应将 | 将死，负 |
| 无子可动且未被将军 | 困毙，负 |
| 同一方连续将军且局面三次重复 | 长将，判负 |
| 双方均无法取胜（三次重复且非长将 / 60 回合无吃子） | 和棋 |

人工提示：进入将军状态时高亮被将军的帅/将，并在 HUD 显示"红方被将军"。

### 8.3 三人回合

- 顺序：**红 s0 → 黑 s1 → 白 s2 → 红**，循环。
- 被淘汰的一方直接从轮转中移除，不产生回合计。
- 三人局不判定"和棋"，改为回合上限（默认 200 个整轮）后按 8.6 计分。

### 8.4 三人特有规则

| 编号 | 规则 | 说明 |
|---|---|---|
| T-1 | 杀将即淘汰 | 任意一方吃掉某家帅/将，被吃方**立即出局**，残子按 T-2 处理 |
| T-2 | 杀将收编 | 败方盘上剩余的 **车、马、炮、未过河的兵/卒** 变色归胜方指挥，位置不变；**士/仕、相/象，以及已过河的兵/卒 直接移出棋盘**；帅/将移出且不复活 |
| T-2a | 已过河兵卒不归降 | "过河"是兵/卒的**棋子状态**，判定时点 = 收编发生的那一瞬。停在渡口（rank 4）但尚未过桥的兵/卒仍算未过河 → **可被收编**；一旦过桥进入他翼（`ownHalf` 为 false）→ 已过河 → **直接移出** |
| T-3 | 收编后状态继承 | 被收编的棋子保留原位置；**被收编的兵/卒必然处于"未过河"状态**，之后沿所在翼朝渡口方向继续前进（rank+1）；到渡口后可过桥，但不回本方翼 |
| T-4 | 将死视同被杀 | 某方被将军且无合法应将时，视同"下一手必被吃"，立即出局；**收编权归将军方** |
| T-5 | 困毙 | 无子可动且未被将军：该方出局，残子**原地清除**（无人收编） |
| T-6 | 最后存活者胜 | 只剩一方时立即结束 |
| T-7 | 将帅照面（隔河对脸） | 三人局的列线在渡口处接上对岸那条线（见 T-12），所以"同一列上无子相隔的两帅"天然成立 = 将军，不需要额外规则。三个渡口顶点两两相连 → 中线上清空后三家老将彼此照面；开局中兵挡在 rank 3，不会误判 |
| T-8 | 兵/卒过河（三人版） | 分四段：**①未过河**（含被收编的兵）只能朝所在翼渡口前进（rank+1），到渡口后过桥；**②已过河、停在河道边**（rank 4）可沿河沿横走 1 格、可续过桥去第三翼（不回本方翼）、也可深入当前翼（rank−1）；**③已过河、深入他翼**（rank ≤ 3）不能退回河道边、不能再过桥，只能继续 rank−1 或横走；**④掉头**：仅当所在翼的将已死（该队出局），才允许 rank+1 退回河道边，再从河边过桥转战第三翼。**"过河"标记一经置位不可撤销**，收编时依此判定去留（T-2a） |
| T-9 | 士/相不可跨区 | 士不出本翼九宫；相/象不出本翼方阵 —— 这也是 T-2 要把防御子移出棋盘的原因（它们无法在别家地盘上作战） |
| T-10 | 不能吃自己的子 | 收编后同一方可能持有 2 个炮、5 个以上兵，规则天然允许，不需要特殊处理 |
| T-11 | 兵/卒不升变 | 无升变规则 |
| T-12 | 河道不断线（v1.4） | **列线走到渡口就等于接上对岸那条列线**：车/炮可以一着沿中线过河，不必先在渡口停一手；**帅的射线同样延伸到对岸（只用于照面判定，走法仍限九宫）**。挡子、炮架在整条线上生效——红兵当炮架时，红中炮能同时打到黑、白两家的中兵。渡口顶点连着**两条**桥（倒三角），所以从顶点出发的射线会分叉成两条，车炮各走一条。横线（rank 方向）不过河，仍然在本翼内 |
| T-13 | 马的路线（v2.0 按图走，完全对称） | 马 = **三段：直行两格 + 拐弯一格**（或镜像），沿着图上实际格子逐格走出来。判定全用图上真实夹角：**直行 ≤ 60°**（行/列线在盘心折了 49–57°，必须算作直行）、**拐弯 66–132°**、**两翼错位处的双浅弯 25–62°**（两翼相差 120°，那里的"斜日"两个折点都只有 30° 左右）。**第一格就是蹩腿点**，且**一个落点只保留一条路线**（先比"少过河"，再比拐角是否最接近 90°，最后比总弯度）——腿唯一，所以腿被堵就跳不过去，和象棋里"蹩马腿"的直觉一致。倒三角：**禁止连续两次过桥**（绕三角转一圈）、回到出发点的路线删除。**跳法必须对称**：能跳过去就能跳回来（有单测钉死，全盘零不对称），因此渡口顶点是**可以落脚**的。结果：渡口顶点 **12** 落点、河沿 **12**、中路旁 **12**、中路 **8**（标准日） |

> **实现注记（v2.3）**：兵的行动分三段——①未过河朝渡口；②河道边（rank 4）可沿河沿横走、
> 续过桥去第三翼、或深入当前翼；③深入后只能继续 rank−1 或横走，不能回河道边、不能再过桥；
> 只有所在翼的将死后才解锁④掉头（rank+1 回渡口，再转战第三翼）。单测 X-16…X-24 覆盖这些分支。

### 8.5 收编的流程时序（必须严格按此顺序，否则会出现"自己吃自己"的中间态）

```
1. 校验合法性（目标格有敌子且为己方合法招）
2. 移除目标格敌方帅/将
3. 遍历棋盘：败方所有 车/马/炮 → owner 改为胜方
4. 遍历棋盘：败方所有 "未过河" 的兵/卒 → owner 改为胜方（位置不变，crossed 保持 false）
5. 遍历棋盘：败方所有 士/仕、相/象、"已过河" 的兵/卒 → 移出棋盘
6. 从轮转序列中移除败方
7. 记录一条 'eliminate' 事件：{victim, killer, converted:[...], removed:[...]}（用于计分与气泡提示；复盘展示尚未实现）
8. 判定是否只剩一方 → 是则终局
```

> **为什么已过河的兵/卒不归降**（设计意图，写进首页规则说明）：
> ① 已过河的兵已断归路、深入敌境，视为"叛离"，不再听命于新主 —— 规则上讲得通；
> ② 平衡上讲，收编只能得到**驻留在败方本方方阵内**的兵（最远到渡口），不会凭空获得一批插在第三家腹地的尖兵，避免"杀一家、得一把快刀直捅第三人"；
> ③ 实现上讲，收编者拿到的一定是未过河兵，后续走法只需按"所在方阵前进方向"处理，不会出现棋子状态与位置矛盾。
>
> 注意第 4 步与第 5 步必须分开遍历：先按**收编前**的 `crossed` 状态把两类兵分桶，再改 owner 或移除；不要边遍历边判断，否则会出现"刚归降的兵被判为已过河"。

### 8.6 三人计分（回合上限后）

`score = 子力分 + 杀王数 × 300`

| 兵种 | 车 | 马 | 炮 | 兵/卒 | 士/仕 | 相/象 | 帅/将 |
|---|---|---|---|---|---|---|---|
| 分值 | 900 | 400 | 450 | 100 | 200 | 200 | 不参与（被吃即出局） |

分高者胜；同分并列为和。该计分只用于"回合上限"和"AI 评估"，不影响对局中的任何走法判定。

## 9. 状态机

```
HOME ──选择模式──▶ PLAYING ──将死/困毙/收编至最后一方/认输──▶ GAME_OVER
  ▲                   │  ▲                                       │
  └──── 返回首页 ──────┘  └──────────── 再来一局 ─────────────────┘
                      │
                 悔棋（POP history，可回到 PLAYING）
```

`GameState` 字段（也是将来存档的格式；当前只有音效开关落盘）：

```ts
interface GameState {
  mode: 'classic' | 'three';
  topology: string;            // 'classic' | 'three'，用于挑选拓扑数据
  cells: (Piece | null)[];     // 长度 = 节点数，按 NodeId 索引
  turn: Team;                  // 'red' | 'black' | 'white'
  order: Team[];               // 剩余玩家顺序（淘汰即移除）
  ply: number;                 // 半回合数
  status: 'playing' | 'over';
  winner: Team | null;
  endReason: string | null;    // checkmate / stalemate / perpetual-check / draw-repetition / draw-60 / resign
  history: Move[];             // 悔棋与记谱（Move 带 gaveCheck / text 标记）
  positions: string[];         // 每次落子后的局面键，长度 = history.length + 1（含开局）
  eliminations: EliminationDetail[]; // 三人局灭国事件流水（victim / killer / converted / removed）
  quiet: number;               // 距上次吃子的半回合数（≥120 判和）
  captured: Piece[];           // 已吃子（侧栏展示）
}
```

> `positions` 与 `quiet` 是为重复局面（长将/三次重复）和无吃子判和服务的：**局面键 = 棋盘占位 + 行动方**，
> 90 个交点固定 90 字符，可直接做字符串比较与计数，不需要 Zobrist 哈希。

### 10.5 动画与音效

| 项目 | 规格 |
|---|---|
| 落子动画 | 棋子从起点缓动到终点，**180 ms**，`easeOutCubic`；动画期间该子从棋盘层跳过，只在插值位置绘制 |
| 吃子 | 被吃子立即移除，不做额外特效（避免遮挡动画） |
| 音效 | WebAudio **现场合成**，不引入任何音频文件：走子（540→430Hz 正弦 90ms）、吃子（300→120Hz 方波 + 低频三角）、将军（760/980Hz 双响）、终局（520/660/880Hz 三连） |
| 开关 | HUD 按钮，写 `localStorage: srxq.sound`；首次点击时 `unlock()` 解除浏览器自动播放限制 |
| 性能 | 动画用 `requestAnimationFrame`，180ms 内约 11 帧，每帧全量重绘（经典 154 段线 / 三人 336 段线）实测无压力 |

### 10.6 中文记谱

| 规则 | 说明 |
|---|---|
| 列号 | 红方用中文数字、从自己右手边数（viewer file 8 → 一，file 0 → 九）；黑方用阿拉伯数字（viewer file 0 → 1） |
| 直线子（车/炮/兵/帅） | `进/退` 后跟**步数**：`车九进一`、`卒5进1` |
| 斜行子（马/相/仕） | `进/退` 后跟**目标列号**：`马八进七` |
| 横走 | `平` + 目标列号：`炮八平五` |
| 同列同兵种 | 用 `前/中/后` 代替起始列号：`前炮进二`、`中兵进一` |
| 三人局 | 无通用记谱，退回「队伍 + 兵种 + 起点→终点」：`红方兵5-4→5-5` |
| 时机 | 记谱在 `playMove` 中**按落子前的局面**计算（同列消歧要用旧棋盘），写进 `Move.text` |

HUD 的「棋谱」行展示最近 8 手。

## 11. AI 设计

### 11.1 双人模式（本期必做）

| 项目 | 方案 |
|---|---|
| 算法 | negamax + alpha-beta 剪枝 + 迭代加深（带时间上限） |
| 难度 | 易：深度 2 / 500 ms；中：深度 3 / 1.5 s；难：深度 4 / 3.5 s（均带时间上限） |
| 评估 | 子力分（见 8.6）+ 位置表（兵过河加分、车占中线加分、九宫守子加分） |
| 走法排序 | MVV-LVA（吃子优先）+ 上次迭代的最佳招优先 |
| 性能目标 | 深度 3 ≤ 1.5 s；深度 4 ≤ 3.5 s（超时回落上一轮结果） |
| 线程 | 同步实现（实测单步均值 19 ms、最慢 111 ms），未迁 Web Worker |

### 11.2 三人模式 AI（后置，二期）

| 方案 | 思路 | 工作量 | 建议 |
|---|---|---|---|
| A · paranoid | 把另外两家视为"联合敌方"，做两人零和搜索 | 小 | **推荐的二期方案** |
| B · maxⁿ | 每方各自最大化自己收益，叶子做三元组评分 | 中 | 评估函数难调 |
| C · 联盟倾向 | 加入"最强者为敌"的启发式 | 大 | 只在 B 之上加权 |

本期三人模式仅**热座（同屏轮流）**。统一入口是 `chooseMove(state, topo, level)`：
`state.order.length === 2` 时走 negamax 搜索，三人局当前回落 `randomMove` 兜底；
二期在 `chooseMove` 内接 paranoid 搜索即可，调用方不用改。
